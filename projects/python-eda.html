01The problem

A file that looks complete, but isn't ready for a decision

A raw export of 10,841 Google Play apps: the same kind of file finance receives every month from a system, a bank or a sales platform. It opens fine and looks complete. It isn't. A commercial team wanted three answers from it: which markets are worth entering, does charging for an app cost installs, and can reviews stand in for installs when install counts aren't available?

Numbers stored as text

Only 2 of 13 columns were usable

"19M", "10,000+" and "$4.99" can't be added, averaged or charted.

Duplicates

1,181 apps appeared more than once

Scraped at different times with different review counts. Totals would be overstated.

Gaps

15% of ratings were blank

Too many to delete, and blanks clustered in small apps, so a simple average would mislead.

Outliers

$400 "premium" apps

Any average price or quality metric would be distorted by joke listings.

02My approach

Treat the file like a trial balance: reconcile first, analyse second

  1. Convert text to numbers, and test the conversionList every shape of value, check the counts add up to the row total, test the function on values checkable by hand, then apply it.Finance parallel: check a formula on three rows with a calculator before filling it down 10,000 rows.
    Show the Python
    def convert_size(size):
    if not isinstance(size, str):
        return np.nan
    size = size.strip()
    if size.endswith('M'): return float(size[:-1]) * 1024 * 1024
    if size.endswith('k'): return float(size[:-1]) * 1024
    return np.nan                        # 'Varies with device': no honest number

convert_size('19M')    # 19,922,944 = 19 x 1024 x 1024 ✓  test before 10,841 rows
df['Size_in_bytes'].isnull().sum()   # 1,695 = the 'Varies with device' count ✓
  2. Reconcile the rows483 identical rows removed, then 698 re-scraped copies, keeping the most-reviewed (latest) version. 10,841 → 9,634, every row explained.Finance parallel: duplicate invoices: keep the latest valid version and explain every line removed.
    Show the Python
    df = df.drop_duplicates()                                  # 483 identical rows
df = df.sort_values('Reviews', ascending=False)          # most-reviewed (latest) copy first
df = df.drop_duplicates(subset='App', keep='first')       # 698 older re-scraped copies
  3. Ask why values are missing before filling themRatings were missing because apps were too small to be rated; sizes were missing for the biggest apps ("Varies with device"). Sizes stay blank on purpose.Finance parallel: if missing receipts all come from one branch, that is a finding, not a gap to plug with the average.
  4. Fill with care, and disclose itEach missing rating filled with the median of apps the same size, every one flagged in a Rating_imputed column, and the 14 unfillable apps removed and documented.Finance parallel: an accrual: a reasoned estimate, clearly labelled and reviewed later.
    Show the Python
    df['Rating_imputed'] = df['Rating'].isnull()               # audit flag, kept for good
median = df.groupby('Installs_category')['Rating'].transform('median')
df['Rating'] = df['Rating'].fillna(median)                   # only the gaps are touched
df['Rating'].isnull().sum()                                    # 14 left: never assume a fill worked
  5. Read the market with the right chartLog scales for skewed data, distributions instead of averages, and market maps instead of totals: 25 charts with titles that state the finding.
  6. Test before concludingPearson, Kruskal-Wallis, Mann-Whitney and a bootstrap confirm which patterns are real, and which are real but too small to matter.Finance parallel: materiality: an auditor reports differences big enough to change a decision, not every difference that exists.
03How it helps the decision

Five answers a commercial team can act on

Pricing

Decide whether to charge, not how much

Free apps get a median 100,000 installs; every paid band gets 1,000. Going from $2 to $15 costs little extra. A freemium model protects reach.

Evidence: price cliff, ECDF and free-vs-paid charts
Market entry

Avoid crowded categories with small typical apps

Business and Medical each have ~400 competitors whose typical app gets about 1,000 installs. Big totals in Game and Communication come from a few giants.

Evidence: market map, treemap and small multiples
Measurement

Use reviews as a proxy for installs

r = 0.96 across six orders of magnitude, about one review per 59 installs. Useful whenever exact install figures aren't available.

Evidence: correlation, pair plot and hexbin charts
Don't chase

The paid-app rating premium is immaterial

Real (+0.09 to +0.17 points) but far too small to justify a pricing decision on its own.

Evidence: bootstrap and significance tests
Don't chase

Update frequency doesn't buy ratings

Recently updated apps rate 4.3; apps idle for two years rate 4.2. Spend the effort elsewhere.

Evidence: update-recency chart
Process

A reusable, audit-ready workflow

The same steps run on a ledger extract, a bank file or a sales export: convert, reconcile, investigate, flag, test.

Evidence: the full notebook (download below)

What this data cannot tell us

  • One snapshot, not a trend. Nothing here shows change over time.
  • Installs are ranges. "10,000+" could be 49,999, so install figures are lower bounds.
  • 15% of ratings are estimates, flagged so they can be excluded.
  • No revenue data. "Successful" here means installed, not profitable.
  • Survivorship bias. Apps pulled before the scrape are missing, which flatters ratings.
